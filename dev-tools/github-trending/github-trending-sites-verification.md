# 추천했던 트렌딩 사이트들, 직접 열어보니 어땠나

지적이 정확했어요. **어떤 기준으로 골랐는지부터 솔직히 말씀드릴게요.**

## 제가 처음 골랐던 기준 (문제의 원인)

지난 답변에서는 **"실제로 사이트를 열어본 게 아니라, 검색 결과에서 여러 블로그/개발자 커뮤니티 글이 반복해서 언급하는 유명한 도구인지"**만 기준으로 골랐어요. 즉:
- 여러 출처에서 자주 인용됨 (평판 기반)
- GitHub 스타 수, 공식 문서 존재 여부

이건 "**한때 유명했다/설계가 좋다**"는 근거는 되지만, "**지금 이 순간 실제로 살아서 정확하게 동작한다**"는 걸 보장하지 못해요. 마치 "맛집 블로그에 많이 나온 식당"이라고 오늘 문을 열었는지 확인 안 하고 추천한 셈이에요.

## 그래서 지금 직접 열어봤어요 (라이브 검증)

| 사이트 | 실제 상태 |
|---|---|
| **OSSInsight** | ⚠️ **문제 확인됨.** 페이지는 뜨지만, 공식 공지로 "GitHub이 이벤트 피드 페이지네이션 방식을 바꿨는데, 우리 수집기가 첫 페이지만 읽고 있었다"고 밝히며 **2025년 중반부터 스타/PR/이슈 순위 업데이트를 중단(pause)**한 상태예요. 지금 트렌딩 순위를 보면 최신 정보가 아니에요. |
| **Trendshift** | ✅ 정상 작동. 오늘(UTC) 기준 데이터가 갱신되고 있음. |
| **Best of JS** | ✅ 정상 작동. "2026-09-01 23:57 (GMT)"처럼 실제 갱신 타임스탬프가 찍혀있고 데이터도 살아있음. |

**결론: 3곳 중 1곳(OSSInsight)은 말씀하신 대로 지금은 신뢰할 수 없는 상태가 맞았어요.** 나머지 둘은 실제로 살아있고 최신이에요.

## 왜 이런 일이 생기나 (일반화하면)

지난 답변([`github-star-tracking-diy.md`](../dev-tools/github-star-tracking-diy.md))에서 다룬 문제의 연장선이에요:
- 이런 트렌딩 사이트들은 전부 **GitHub의 비공식/준공식 데이터 파이프라인**에 의존해요.
- GitHub이 API 응답 방식(페이지네이션 등)을 조용히 바꾸면, 그걸 감지 못한 수집기는 **에러 없이 "조용히" 잘못된/오래된 데이터를 계속 보여줘요.** (다운되는 게 아니라 "썩은 채로" 살아있는 게 더 무서운 경우)
- 그래서 이런 서비스는 **"떠 있냐"가 아니라 "데이터가 최신이냐"를 따로 확인**해야 해요.

## 반성: 앞으로 이렇게 할게요
검색으로 도구/사이트를 추천할 때, **평판(언급 빈도)과 실제 라이브 상태(직접 접속 확인)를 구분해서 답변**할게요. "유명하다"와 "지금 정상 작동한다"는 다른 질문이라는 걸 짚어주셔서 정확히 잡혔습니다.
