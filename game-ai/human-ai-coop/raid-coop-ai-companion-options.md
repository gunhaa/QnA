# 레이드 협동 AI 동료 만들기 — 게임 선택지와 "직접 만들기" 판단

## 쉬운 설명

레이드 AI 도우미를 만들려면 **먼저 정해야 할 게 있어요. AI가 "직접 플레이"하나요, 아니면 "옆에서 알려주기만" 하나요?**

- **직접 플레이** → 상용 게임은 거의 다 막혀 있어요. 와우는 "애드온이 대신 스킬을 쓰는 것"을 시스템 차원에서 차단합니다. 대신 **내 서버를 직접 돌리면** 됩니다 (AzerothCore라는 오픈소스가 있어요).
- **알려주기만** → 와우 애드온으로 **합법적으로 가능합니다.** 화면에 "지금 피해!" 띄우는 건 허용돼요.

그리고 **"내가 만드는 게 빠를 것 같다"는 감, 맞습니다.** 이 분야 연구자들도 **전부 직접 만들어 씁니다.** 상용 게임 쓰는 사람이 없어요. 빨리감기가 안 되고, 기록도 안 남고, 규칙도 못 바꾸거든요.

---

## 일반 설명

### 0. 먼저 갈라야 할 질문 — AI가 **행동**하나, **조언**하나

이 하나로 선택지가 완전히 갈립니다.

| | **행동형 (에이전트)** | **조언형 (어드바이저)** |
|---|---|---|
| 역할 | 레이드 슬롯을 차지하고 직접 플레이 | 상태를 읽고 인간에게 지시·경고 |
| 상용 게임 | **거의 전부 금지** | **와우는 공식 허용** |
| 연구 가치 | 높음 (협응 알고리즘 그 자체) | 중간 (설명·타이밍·UX) |
| 실사용자 확보 | 어려움 | **쉬움 (애드온 배포)** |

두 가지를 동시에 할 수는 없습니다. 어느 쪽이 하고 싶은지부터 정하는 게 순서입니다.

---

### 1. 상용 게임 선택지 검토

#### 1.1 World of Warcraft (리테일) — **조언형만 가능**

와우의 애드온 Lua API는 **공식 지원**이지만, 전투 자동화를 **시스템 차원에서 차단**합니다.

- **보호 함수(protected functions)**: 전투 중 애드온이 **이동·타겟팅·스킬 시전**을 할 수 없습니다. **실제 키 입력만 트리거할 수 있습니다.**
- **taint(오염) 시스템**: 서드파티 코드나 데이터를 읽는 순간 실행 흐름이 "오염"으로 표시되어 보호 경로를 못 탑니다.
- 이 구조는 패치 2.0부터 도입됐고, 그 전에는 애드온이 **타겟 선정과 스킬 시전을 대대적으로 자동화**할 수 있었기 때문에 막은 것입니다.

**단, 조언은 명시적으로 허용됩니다** — 애드온은 **화면에 다음 스킬을 제안**할 수 있고, 다만 플레이어 대신 결정을 내리지는 못합니다.

> **즉 "AI 레이드 코치"는 리테일 와우에서 완전히 합법적으로 만들 수 있습니다.** 전투 로그·쿨다운·보스 캐스트바·파티원 상태를 다 읽을 수 있으니 재료는 충분합니다. 실사용자 확보도 가장 쉬운 경로입니다 (CurseForge 배포).

#### 1.2 ⭐ AzerothCore + mod-playerbots — **행동형의 현실적 답**

오픈소스 WoW 서버 에뮬레이터(3.3.5a / WotLK)입니다. **내 서버를 내가 돌리므로 ToS 문제가 없습니다.**

| 항목 | 내용 |
|---|---|
| **mod-playerbots** | 플레이어 같은 봇을 서버에 추가하는 모듈. **봇들이 대부분의 레이드와 전장을 수행** |
| 기능 | 퀘스트·파밍·던전/레이드 참가·전장·사회적 상호작용. 내 부캐를 봇으로 로그인시켜 파티 구성 가능 |
| 2026 현황 | **활발히 유지보수 중.** trickerer의 `mod-playerbots` 포크가 현재 AzerothCore 빌드와 호환되는 권장 경로 |
| 일부 포크의 확장 | **AI 봇 채팅, 영속 레이드 로스터, 스크립트 레이드 보스 AI**, 웹 등록 사이트 |

**장점**: 진짜 와우 레이드 메커닉, 실제 인카운터, 8~25인 규모, 데모 영상으로서의 설득력이 압도적.
**단점**: C++ 대형 코드베이스, **실시간만 가능**(빨리감기 불가), WotLK 고정, 서버 세팅 부담.

> **연구 평가용으로는 부적합하고, 데모/포트폴리오용으로는 최고**입니다. 1만 에피소드를 밤새 돌리는 게 불가능합니다.

#### 1.3 Dota 2 Bot Scripting API — **유일하게 "공식 + 인간과 혼합"**

Valve가 **공식 Lua 봇 스크립팅 API**를 제공합니다.

- 게임 실행 중 **제한된 Lua 5.1 VM**에서 스크립트 실행. `hero_selection.lua`, `bot_generic.lua`, `ability_item_usage_generic.lua` 등 구조화된 파일 체계.
- **커스텀 로비에서 AI vs AI, AI vs Valve Bot, AI vs 인간** 모두 가능. **인간과 봇이 같은 팀으로 섞이는 것도 됩니다.**
- 커뮤니티 구현 다수 (127영웅 대응 스크립트 등).

레이드는 아니지만 **5인 역할 협응**이라는 점에서 구조적으로 가장 가깝고, **공식 지원 + 실제 인간 플레이어**라는 조합이 유일합니다.

> ⚠️ **확인 필요**: 제한된 Lua 5.1 VM에서 **외부 네트워크 호출(LLM API)이 가능한지 확인하지 못했습니다.** 샌드박스 특성상 막혀 있을 가능성이 높고, 그렇다면 BASIL과 같은 문제에 부딪힙니다. 이 경로를 택한다면 **가장 먼저 검증할 항목**입니다.

#### 1.4 FFXIV Duty Support / Trust — 만들 건 아니고, **설계 교본**

스퀘어에닉스가 실제로 출시한 AI 파티 시스템입니다. API는 없지만 **배울 게 많습니다.**

- 파티 구성을 **자동으로 2 DPS / 1 탱커 / 1 힐러** 균형에 맞춰 배정.
- NPC는 플레이어를 따라다니고, **떨어지면 순간이동**해서 붙습니다.
- **핵심 교훈 1: 여러 던전 메커닉을 NPC에 맞춰 다시 설계했습니다.** 기존 콘텐츠를 그대로 두고 AI를 끼워 넣은 게 아닙니다.
- **핵심 교훈 2: NPC가 의도적으로 데미지를 낮추거나 높여** 던전 소요 시간을 평균 30분에 맞춥니다.

> **이게 가장 값진 실무 교훈입니다 — AI 동료를 "출시"한다는 건 콘텐츠를 AI와 함께 재설계한다는 뜻입니다.** 기존 레이드 인카운터를 그대로 두고 AI가 알아서 해내길 바라는 접근은 세계 최대 MMO 개발사도 택하지 않았습니다.

### 2. "직접 만드는 게 빠를 것 같다" — 맞습니다. 그게 이 분야의 표준입니다

이건 게으른 선택이 아니라 **분야의 정석**입니다. 앞 문서에서 본 human-AI coordination 벤치마크를 다시 보면:

| 벤치마크 | 환경 출처 |
|---|---|
| Overcooked-AI | **연구용으로 직접 제작** |
| Collab-Overcooked | **직접 제작** |
| Collab Capture / Collab Escape | **직접 제작** |
| AH2AC2 | Hanabi(보드게임) + **직접 만든 평가 하네스** |

**상용 게임을 쓰는 human-AI coordination 벤치마크는 사실상 없습니다.** 이유가 명확합니다:

| 필요한 것 | 상용 게임 | 직접 만든 환경 |
|---|---|---|
| **헤드리스 + 빨리감기** (1만 에피소드 야간 실행) | ❌ | ✅ |
| 결정론적 시드 + 리플레이 | ❌ | ✅ |
| 전체 관측·행동 로깅 | ❌ | ✅ |
| **메커닉 단위 ablation** ("소각 메커닉만 빼고 실험") | ❌ | ✅ |
| ToS 위험 | 있음 | 없음 |
| 인간 플레이어 확보 | 쉬움 | **어려움** ← 유일한 단점 |

**단점이 하나뿐이고, 그건 앞 문서의 AH2AC2 방식(human proxy)으로 상당 부분 우회됩니다.**

---

### 3. 직접 만든다면 — 반드시 넣어야 할 5가지

여기가 진짜 설계 지점입니다. **레이드를 레이드답게 만드는 요소를 빠뜨리면 그냥 Overcooked 재탕**이 됩니다.

| # | 요소 | 빠뜨리면 생기는 일 |
|---|---|---|
| **1** | **역할 상호의존** — 탱커가 어그로를 잡아야 힐러가 탱커만 보고, 그래야 딜러가 딜에 집중. 내 최적 행동이 **남의 행동에 의존** | 각자 독립 최적화로 풀려버림. 협응 문제가 아니게 됨 |
| **2** | **타이밍 강제 메커닉** — 산개/집결, 인터럽트 로테이션, 장판 소각(soak), 쫄 처리. **정해진 시점에 정해진 인원이** 해야 함 | 반응만 잘하면 되는 문제로 퇴화 |
| **3** | **부분 관측 + 제한된 소통** — 전부 못 봄. **콜아웃이 의미를 가져야 함** | 완전정보가 되면 마음이론(theory of mind)이 불필요해짐 |
| **4** | **실패 연쇄** — 한 명이 놓치면 전멸. **보상이 비선형** | 선형 보상이면 "각자 열심히"로 풀림 |
| **5** | ⭐ **인간은 예측 불가하고 때로 틀린다** — AI가 **최적 플레이를 가정하지 않고 보정**해야 함 | 이게 빠지면 self-play 최적화로 끝. **인간과는 오히려 안 맞는 정책**이 나옴 (zero-shot coordination 문제) |

**5번이 가장 중요하고 가장 자주 빠집니다.** 앞 문서에서 본 것처럼, 이 분야의 핵심 난제는 "AI를 강하게 만들기"가 아니라 **"파트너에 맞추기"** 입니다. 파트너가 실수할 수 있는 환경이 아니면 그 문제 자체가 발생하지 않습니다.

**빼도 되는 것**: 그래픽, 성장/경제, 오픈월드, 아이템, 다양한 직업. **보스 1~3종 + 역할 3종이면 충분합니다.**

#### 권장 구현 형태

```
Python, 헤드리스, Gym 스타일 API
  - 틱 기반 (실시간 아님) → 빨리감기 가능
  - 관측: 구조화된 딕셔너리 (텍스트 직렬화 쉬움)
  - 행동: 이산 (스킬 사용, 이동, 콜아웃)
  - 시드 고정 + 전체 리플레이 저장
  + 얇은 인간 플레이용 뷰어 (웹 또는 pygame)
    ※ 같은 환경을 사람이 직접 플레이할 수 있어야 함
```

v1 범위(보스 1종, 역할 3종, 메커닉 4~5개)는 **현실적으로 2~4주**입니다. AzerothCore 세팅과 C++ 봇 AI 수정에 드는 시간과 비교하면 확실히 빠릅니다.

### 4. 경로별 추천

| 목표 | 경로 | 비고 |
|---|---|---|
| **협응 알고리즘 연구가 목적** | ⭐ **직접 제작** (2~4주 v1) | 분야 표준. 빨리감기·로깅·ablation 전부 확보 |
| **보여주기·포트폴리오가 목적** | **AzerothCore + mod-playerbots** | 진짜 와우 레이드. 데모 설득력 최고, 평가는 불가 |
| **실사용자를 빨리 얻고 싶다** | **와우 리테일 어드바이저 애드온** | 합법, CurseForge 배포, 실제 레이더들이 씀 |
| **공식 지원 + 인간과 혼합 팀** | **Dota 2 Bot API** | 유일한 조합. **단 LLM 네트워크 호출 가능 여부 선검증** |

**추천 조합: 직접 제작 + 어드바이저 애드온.**

- 직접 만든 환경에서 **협응 알고리즘을 개발·평가**하고 (빠른 반복, 객관적 지표),
- 같은 로직을 **와우 어드바이저로 이식해 실제 인간 사용자에게 검증**합니다.

이러면 연구 품질과 실사용 증거를 둘 다 얻습니다. 그리고 어드바이저는 **행동 권한이 없어서** 오히려 안전하고 합법적이며, **"AI가 인간의 실수를 보정한다"는 5번 요소를 실제 인간에게서 관찰**할 수 있습니다.

### 5. 놓치기 쉬운 점

1. **FFXIV의 교훈을 초반에 적용하세요.** 인카운터를 AI와 **함께** 설계하세요. 사람용으로 만든 뒤 AI를 끼워 넣으면 스퀘어에닉스가 겪은 재설계를 반복하게 됩니다.

2. **인간 파트너의 "틀림"을 1급 시민으로 모델링하세요.** 실수 확률, 반응 지연, 메커닉 오인 — 이걸 환경 파라미터로 넣어야 5번 요소가 살아납니다. AH2AC2의 human proxy가 정확히 이 역할이고, 그쪽 접근을 빌려올 수 있습니다.

3. **콜아웃을 행동 공간에 넣으세요.** 레이드의 본질 중 하나가 소통입니다. AI가 "3시 방향 산개" 같은 발화를 **행동으로** 낼 수 있어야 하고, 그게 인간에게 실제로 도움이 되는지가 평가 항목이 됩니다. LLM의 강점이 정확히 여기입니다.

4. **평가 지표를 미리 정하세요.** 클리어율뿐 아니라 — 인간 파트너의 실수 후 회복률, 콜아웃 유용성(인간 평가), 처음 보는 인간 파트너와의 성능(ad-hoc), 인간이 느끼는 예측 가능성.
