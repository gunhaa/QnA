# RAG 운영 시 흔한 함정과 해결 방법

## 쉬운 설명

사서가 일을 잘 못하는 건 대개 사서 탓이 아니라 **카드를 만든 사람 탓**이다. 표를 찢어서 카드에 붙이거나, 옛날 판 책 카드를 안 버리거나, "모르면 모른다고 하세요"라는 말을 안 해 두면 사서는 엉뚱한 쪽을 들고 와서 자신 있게 답한다. 그리고 카드가 잘 만들어졌는지 **시험을 한 번도 안 보면** 무엇이 문제인지 끝까지 모른다.

## 일반 설명

원인이 사용자(코드·설정·운영 절차)에 있는 문제들이다. 대상 자체가 제 기능을 못 하는 경우는 [장애 유형](./05-failure-modes.md)에 있다.

### 1. 평가 세트 없이 튜닝 (안티패턴)

- **증상**: 분할 크기·top-k·프롬프트를 바꿀 때마다 질문 몇 개를 손으로 넣어 보고 "좋아진 것 같다"로 결정한다. 한쪽을 고치면 다른 질문이 조용히 나빠진다.
- **원인**: 검색과 생성을 나눠 측정하는 기준이 없다.
- **해결**:
  - 50~200문항, 문항마다 **정답 문서와 근거 위치**를 둔 골든 세트를 만든다. 20~30%는 "문서에 답이 없음" 같은 경계 사례로 채운다.
  - **검색 단계**(Hit@k, MRR, nDCG, Context Recall)와 **생성 단계**(Faithfulness, Answer Relevancy)를 따로 잰다. 검색이 틀린 문제를 프롬프트로 고치려 하지 않게 된다.
  - 변경마다 같은 세트로 돌리고, 핵심 지표(예: Hit@5)를 CI 기준으로 둔다 → [RAG 평가 방법과 도구](../../../inquiry/ai/0047-rag-evaluation-benchmark-methods-and-tools.md), [LLM 없이 검색만 자동 평가](../../../inquiry/ai/0048-retrieval-only-eval-automation-allganize-dataset.md).

### 2. 파싱 결과를 눈으로 안 봄 (실수)

- **증상**: 표가 있는 질문만 틀린다. 답에 머리글·쪽 번호·"대외비" 문구가 섞인다.
- **원인**: PDF·xlsx를 범용 추출기로 텍스트화하면서 표 행·열 관계가 사라지거나 다단 레이아웃 순서가 뒤섞였다.
- **해결**: 형식별로 대표 문서 10~20개를 파싱해 결과를 직접 확인한다. 표는 행 단위 "열이름: 값" 문장이나 Markdown 표로 바꾼다. 실패를 파싱·분할·검색·순위 중 어디서 났는지 분류하면 파싱 문제가 의외로 많다 → [사내 RAG 데이터 유형과 파서](../../../inquiry/ai/0043-internal-rag-data-types-and-parsers-spring-ai.md).

### 3. 고정 길이 분할로 조항·표를 자름 (실수)

- **증상**: "제12조 2항"을 물으면 1항만 나오거나, 조건과 예외가 다른 조각으로 갈라져 반쪽짜리 답을 한다.
- **해결**: 제목·조항 경계로 먼저 나누고, 긴 섹션만 다시 나눈다. 조각 앞에 **제목 경로(breadcrumb)**를 붙여 조각만 봐도 어느 문서 어느 절인지 알게 한다. 작은 조각으로 찾고 상위 섹션을 넣는 parent-child 구성도 쓴다.

### 4. 벡터 검색만 사용 (실수)

- **증상**: 뜻으로 묻는 질문은 잘 되는데 조항 번호·제품 코드·사람 이름·약어로 물으면 엉뚱한 조각이 나온다.
- **원인**: 임베딩은 의미를 압축하면서 정확한 문자열 정보를 잃는다.
- **해결**: 키워드 검색(BM25·FTS)을 함께 돌려 RRF로 합친다. 한국어는 공백 단위 토큰화로는 조사가 붙어 매칭이 안 되므로 형태소 분석이나 2-gram 색인을 쓴다 → [pg_bigm](../../../inquiry/database/0014-pg-bigm-vs-like-search.md).

### 5. 질문과 문서의 임베딩 조건 불일치 (실수)

- **증상**: 검색 점수가 전반적으로 낮고 순위가 무작위처럼 보인다.
- **원인**: 질문과 문서를 서로 다른 모델·버전·차원으로 임베딩했거나, 모델이 요구하는 접두어(예: e5 계열의 `query:`/`passage:`)나 정규화를 한쪽에만 적용했다.
- **해결**: 조각마다 `embedding_model`(모델·버전·차원)을 저장하고, 질의 시 같은 값인지 확인한다. 모델 교체는 **전체 재임베딩 후 색인 교체**로만 한다 (부분 재임베딩 금지).

### 6. 유사도 점수를 절대 기준으로 믿음 (오해)

- **오해**: "코사인 0.8 이상이면 관련 있다."
- **실제**: 점수 분포는 모델·언어·문서 길이마다 다르다. 어떤 모델은 무관한 문장끼리도 0.7을 넘는다. 고정 임계값은 모델을 바꾸면 그대로 깨진다.
- **해결**: 임계값은 평가 세트에서 "답 없음" 질문과 정답 질문의 점수 분포를 보고 정한다. 재순위화 점수가 관련성 판단에 더 안정적이다.

### 7. 조각을 많이 넣을수록 좋다 (오해)

- **오해**: top-k를 20, 30으로 늘리면 정답이 들어갈 확률이 올라가니 더 좋다.
- **실제**: 재현율은 오르지만 무관한 조각이 섞여 모델이 엉뚱한 근거를 인용하고, 가운데 놓인 정보는 덜 쓰인다(Lost in the Middle). 토큰 비용과 지연도 늘어난다.
- **해결**: 넓게 찾고(50개) 재순위화로 좁혀(5개 안팎) 넣는다. 가장 관련 높은 조각을 맨 앞이나 맨 뒤에 둔다.

### 8. "근거가 없으면 모른다고 답하라"를 안 정함 (실수)

- **증상**: 문서에 없는 질문에 일반 상식으로 그럴듯하게 답한다. 사내 규정 챗봇이 "보통 연차는 이월이 안 됩니다" 같은 외부 상식을 말한다.
- **해결**:
  - 시스템 지시에 "제공된 근거로만 답하고, 없으면 없다고 답하라. 근거 번호를 인용하라"를 둔다.
  - 검색 결과가 비거나 점수가 기준 미만이면 **LLM을 부르지 않고** 정해진 안내문을 돌려준다 (Spring AI `ContextualQueryAugmenter.allowEmptyContext(false)`).
  - 평가 세트에 "답 없음" 문항을 넣어 거절률을 잰다. RGB 벤치마크(AAAI 2024)에서는 여러 LLM이 근거가 없을 때 거절하는 비율이 50%에 못 미쳤다.

### 9. RAG가 환각을 없앤다 (오해)

- **실제**: 환각이 줄 뿐이다. 모델은 근거를 잘못 읽거나, 두 조각을 섞어 없는 사실을 만들거나, 근거와 다른 내용을 인용 번호와 함께 쓸 수 있다.
- **해결**: 답변의 주장마다 인용을 요구하고, Faithfulness(답이 근거에서 나왔는가)를 따로 잰다. 규정·법무처럼 틀리면 안 되는 영역은 원문 조항을 그대로 보여 준다.

### 10. 권한 필터를 검색 뒤나 생성 뒤에 검 (실수, 보안)

- **증상**: 일반 직원 질문에 인사팀 전용 문서 내용이 섞여 나온다. 또는 권한 필터 뒤 결과가 0~1개로 줄어 답을 못 한다.
- **원인**: 벡터 검색으로 상위 k개를 먼저 뽑고 나서 권한으로 걸렀다(사후 필터). 걸러진 만큼 결과가 비고, 걸러 내지 못하면 누출된다.
- **해결**: 조각에 권한 메타데이터(ACL)를 원본 문서에서 상속해 저장하고, **검색 질의 안에서** 필터한다. pgvector는 필터가 선택적이면 HNSW 결과가 모자랄 수 있으므로 반복 스캔(`hnsw.iterative_scan`, 0.8.0+)을 켜거나 파티션을 나눈다. OWASP LLM08:2025(Vector and Embedding Weaknesses)가 이 위험을 다룬다.

### 11. 문서 속 지시문을 그대로 믿음 (실수, 보안)

- **증상**: 색인된 문서나 웹 페이지 안의 "이전 지시를 무시하고 …" 문장을 모델이 따른다 (간접 프롬프트 주입, OWASP LLM01).
- **해결**: 검색 결과를 프롬프트에서 **데이터 영역**으로 구분하고(태그로 감싸기), 지시를 따르지 말라고 명시한다. 도구 호출 권한을 최소로 둔다(검색 챗봇이 메일 전송 도구를 가지지 않게). 외부 출처 문서는 색인 전에 검토하거나 출처별로 신뢰도를 나눈다.

### 12. 버전·효력일 없이 색인 (실수)

- **증상**: 개정 전 규정으로 답한다. 같은 조항의 옛판과 새판이 함께 검색돼 서로 모순된 답을 한다.
- **해결**: 문서 단위로 버전·효력일·상태를 두고, 새 버전을 색인할 때 **옛 조각을 같은 트랜잭션에서 비활성화**한다. 내용 해시(SHA-256)로 바뀐 문서만 재색인한다.

### 13. 후속 질문을 그대로 검색 (실수)

- **증상**: "연차 규정 알려줘" 다음 "그럼 이월은?"을 물으면 "이월"만으로 검색해 다른 제도의 이월 규정이 나온다.
- **해결**: 대화 맥락으로 **독립 질문을 다시 쓴 뒤** 검색한다 (질의 재작성, Spring AI `RewriteQueryTransformer`·`CompressionQueryTransformer`).

### 14. 에이전트에 검색 상한·강제가 없음 (실수)

- **증상**: 도구 호출형 RAG에서 모델이 검색하지 않고 사전 지식으로 답하거나, 반대로 검색을 열 번 넘게 반복해 지연·비용이 튄다.
- **해결**: 도메인 질문에는 검색을 먼저 하도록 지시하고(필요하면 첫 턴에 도구 호출 강제), 도구 호출 횟수·총 토큰 상한을 둔다. 로그에 "검색 0회 답변" 비율을 남겨 감시한다.

### 15. 점검 체크리스트

- [ ] 골든 세트(정답 문서·근거 위치, 답 없음 문항 포함)가 있고 변경마다 돌리나
- [ ] 형식별 파싱 결과를 직접 확인했나
- [ ] 분할이 제목·조항·표 경계를 따르고 제목 경로를 붙이나
- [ ] 벡터 + 키워드 하이브리드인가, 한국어 토큰화가 맞나
- [ ] 조각마다 임베딩 모델·버전이 기록돼 있나
- [ ] 임계값을 평가 데이터로 정했나
- [ ] 근거가 없을 때 거절하나, 인용을 강제하나
- [ ] 권한 필터가 검색 질의 안에 있나
- [ ] 검색 결과가 프롬프트에서 데이터로 구분되나
- [ ] 문서 버전·효력일과 옛 조각 비활성화가 있나
- [ ] 후속 질문을 재작성하나, 도구 호출 상한이 있나
