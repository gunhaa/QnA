# Q&A: 토큰화 후 "치환"하는 voca 테이블과, 연산에 쓰는 벡터가 같은 테이블인가요?

## 질문 요약

> tokenize 한 후 토큰을 매핑테이블로 이해하고 있는 voca로 치환하는 거임? 그리고 그 voca는 매핑테이블의 벡터값을 그대로 사용해서 연산하는 거고?

## 짧은 답

**절반은 맞고, 절반은 표현을 살짝 고쳐야 해요.** 사실 테이블이 **하나가 아니라 둘**이에요. 이 둘을 구분하는 게 이번 질문의 핵심입니다.

1. **어휘집(Vocabulary) 테이블** — 글자 조각 ↔ 번호(ID)만 짝지어놓은 표. **벡터 없음.**
2. **임베딩 테이블(Embedding Table)** — 그 번호를 받아서 진짜 벡터(숫자 리스트)로 바꿔주는 표. **여기 벡터가 있음.**

즉, "토큰을 voca로 치환한다"는 정확히는 **"글자를 잘라서 voca 사전에 있는 번호(ID)로 바꾼다"**는 뜻이고, 그다음에 **별도의 임베딩 테이블에서 그 번호에 해당하는 벡터를 꺼내오는** 것이 2단계예요. 두 표가 하는 일이 다릅니다.

## 비유로 다시 보기

- **어휘집(Vocabulary)** = 사물함 번호표. "낮은"이라는 글자 조각에는 305번 사물함이 배정되어 있다는 것만 알려줘요. 사물함 안에 뭐가 들었는지는 몰라요.
- **임베딩 테이블(Embedding Table)** = 진짜 사물함 내용물. 305번 사물함을 열어보면 그 안에 "이 단어의 의미를 나타내는 숫자 리스트(벡터)"가 들어있어요.

번호표(어휘집)만 봐서는 "305번이 뭘 뜻하는지" 전혀 알 수 없고, 사물함(임베딩 테이블)을 직접 열어야 진짜 정보(벡터)가 나옵니다.

## 왜 두 개로 나뉘어 있나요?

| 구분 | 어휘집 (Vocabulary) | 임베딩 테이블 (Embedding Table) |
|---|---|---|
| 저장하는 것 | 글자 조각 문자열 ↔ 정수 ID | 정수 ID ↔ 벡터(숫자 리스트) |
| 언제 만들어지나 | 토크나이저를 **학습**할 때 (BPE 병합 과정에서) 딱 한 번 결정됨 | 모델을 **학습**할 때 계속 값이 업데이트됨 |
| 학습 중 값이 바뀌나요? | **안 바뀜.** 한번 정해지면 고정 (마치 사전 편찬 끝난 국어사전처럼) | **계속 바뀜.** 모델이 문장을 많이 볼수록 벡터 값이 조금씩 수정됨 |
| ID 숫자 자체에 의미가 있나요? | **없음.** 305번이 306번보다 304번에 더 가깝다는 규칙 같은 건 없어요. 그냥 색인 번호일 뿐이에요. | 벡터의 **방향과 거리에 의미가 있음.** 비슷한 뜻의 단어는 벡터가 서로 가까워짐 |

핵심 포인트: **토큰 ID 숫자 자체는 아무 의미가 없는 "색인 번호"**예요. 500번이 501번과 가깝다는 뜻이 절대 아니에요. 그냥 임베딩 테이블에서 "몇 번째 줄을 꺼내올지" 가리키는 화살표일 뿐입니다. 진짜 의미(뜻이 비슷한지 다른지)는 임베딩 테이블 안의 **벡터 값**에만 담겨 있어요.

## 두 번째 질문: "그 벡터값을 그대로 연산에 쓰는가?"

네, 맞습니다. 임베딩 테이블에서 꺼낸 벡터는 **가공 없이 그대로** 다음 단계(포지셔널 인코딩을 더하고, 이후 어텐션/FFN 계산)의 입력으로 들어갑니다. 별도로 한 번 더 변환하거나 하지 않아요.

다만 두 가지를 덧붙이면 더 정확해요.

1. **입력에서 쓰인 뒤에도 계속 가공됩니다.** 임베딩 벡터 자체는 그대로 시작점으로 쓰이지만, 그 다음 어텐션 층에서 Q/K/V로 변환되고, FFN에서 또 변환되면서 층을 지날 때마다 벡터가 계속 새로운 값으로 업데이트돼요. "최초 입력 벡터"로만 순수하게 쓰이는 거예요.
2. **이 벡터는 모델의 "가중치(파라미터)"입니다.** 즉 학습 데이터가 아니라 모델 그 자체의 일부예요. 그래서 같은 단어가 어느 문장에 나오든, 학습이 끝난 뒤에는 항상 같은 시작 벡터를 갖고 시작합니다 (문맥에 따라 달라지는 건 그 이후 어텐션 층을 지나면서부터예요).

## 전체 흐름 다시 그리기

```
"낮은 산" (원문 텍스트)
   ↓ [토크나이저] 어휘집(Vocabulary) 참조 — 벡터 없음, ID만 매핑
[1024, 7, 305]  ← 그냥 색인 번호들
   ↓ [임베딩 레이어] 임베딩 테이블(Embedding Table) 참조 — 여기서 진짜 벡터가 나옴
[[0.1,-0.4,...], [0.9,0.2,...], [0.3,-0.1,...]]  ← 각 번호에 대응하는 학습된 벡터
   ↓ 이 벡터를 그대로(가공 없이) 다음 단계(포지셔널 인코딩, 어텐션...)의 입력으로 사용
```
