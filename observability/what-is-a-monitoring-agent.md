# 에이전트(Agent)란 어떤 프로그램인가? — 하드웨어마다 심는 "꼬마 관리인"

## 결론부터: 질문하신 이해가 거의 맞아요

> "주기적으로 어딘가에 정보를 주고, 화이트리스트에서 요청이 오면 무언가를 수행하는 프로그램"

네, 정확히 그런 프로그램이 맞습니다. 다만 한 가지 짚을 부분이 있어요 — 에이전트는 **"서버"라기보다는 대부분 "손님(클라이언트)"에 더 가까워요.** 왜 그런지 아래에서 자세히 설명할게요.

## 비유: 아파트마다 배치된 "관리 도우미"

큰 아파트 단지(전체 시스템)를 관리한다고 생각해보세요. 본부(중앙 서버)에 관리소장님이 앉아서 모든 집을 직접 돌아다니며 확인할 수는 없어요. 그래서 **각 집(하드웨어 한 대)마다 도우미 한 명씩을 상주시켜요.** 이 도우미가 바로 **에이전트(Agent)**입니다.

이 도우미는 매일 하는 일이 정해져 있어요.

1. **정기 보고**: 정해진 시간마다(예: 15초, 1분마다) "우리 집 전기 얼마나 썼는지, 수도는 잘 나오는지"를 본부에 스스로 전화해서 알려줘요.
2. **지시 수행**: 본부에서 "이 집 보일러 좀 꺼줘" 같은 요청이 오면, 미리 등록된(신뢰할 수 있는) 본부의 요청인지 확인한 뒤 실행해요.

## 기술적으로 정확히 뭔가요?

**에이전트(Agent)**는 관리 대상 하드웨어(서버, PC, IoT 장비 등) 위에서 항상 켜져서 돌아가는 **백그라운드 프로그램(데몬, Daemon)**입니다. 리눅스에서는 보통 `systemd` 같은 초기화 시스템이 이 데몬을 백그라운드 프로세스로 띄워서 관리해요.

역할은 크게 두 가지예요.

- **데이터 수집 및 전송(Collector + Forwarder)**: CPU 사용률, 메모리, 디스크, 프로세스 목록, 로그 같은 정보를 주기적으로 긁어모아서 중앙 서버로 보내요. (Datadog 에이전트의 경우 실제로 내부가 "Collector"와 "Forwarder"라는 두 부품으로 나뉘어 있어요.)
- **명령 실행(Command Executor)**: 중앙에서 내려온 설정 변경, 점검(check) 실행, 특정 작업 지시를 받아 그 하드웨어 위에서 대신 실행해줘요.

## "서버냐 클라이언트냐" — Push 방식과 Pull 방식

이 부분이 질문의 핵심인데, 사실 **두 가지 방식이 다 존재**해요.

### Push 방식 (에이전트가 먼저 말을 거는 방식) — 대부분 이렇게 동작

- 에이전트가 **능동적으로** 주기적으로 중앙 서버에 접속해서 "저 이번 주기 데이터 여기 있어요" 하고 데이터를 보내요.
- 이 방식에서 에이전트는 오직 **바깥으로 나가는 연결(outbound connection)**만 만들어요. 즉, 에이전트 입장에서는 자신이 **클라이언트**이고, 중앙 서버가 진짜 서버예요.
- 장점: 하드웨어가 방화벽 뒤에 있거나 클라우드처럼 외부에서 직접 접속하기 어려운 환경에서도 잘 동작해요. (에이전트가 알아서 나가니까요.)
- 대표 예: Datadog 에이전트가 이 방식이에요.

### Pull 방식 (본부가 찾아와서 물어보는 방식)

- 에이전트는 평소엔 조용히 대기(listen)만 하고 있다가, 중앙 서버가 특정 포트로 접속해서 "지금 상태 좀 줘봐" 하고 요청하면 그때 응답해요.
- 이 경우엔 에이전트가 **작은 서버처럼** 동작하는 게 맞아요 — 요청을 받아서 응답하는 쪽이니까요. (예: Checkmk의 pull 모드 에이전트는 TCP 6556 포트에서 대기하다가 서버 질의에만 응답해요.)

즉, 방식에 따라 에이전트가 "클라이언트"일 수도, "미니 서버"일 수도 있어요. 다만 최근 클라우드/보안 환경에서는 Push 방식(에이전트=클라이언트)이 훨씬 널리 쓰이는 추세예요 — 방화벽 구멍을 뚫을 필요가 없어서 관리가 훨씬 쉽거든요.

## 화이트리스트(신뢰 목록)는 어디서 작동하나요?

말씀하신 "화이트리스트에서 요청이 오면 실행"하는 개념은 보안 관점에서 정확해요. 실제로는 이렇게 구현돼요.

- 에이전트는 아무 요청이나 실행하지 않고, **미리 등록된 중앙 서버(또는 인증서/토큰으로 검증된 출처)**의 요청만 신뢰해요.
- 이걸 위해 보통 **상호 TLS 인증(mTLS)**, **API 키**, **에이전트 컨트롤러(Agent Controller)**라는 별도 부품이 인증을 담당해요.
- 이렇게 하면 악의적인 제3자가 가짜 명령을 보내서 하드웨어를 마음대로 조종하는 걸 막을 수 있어요.

## 요약 그림

```
[하드웨어 A]                    [하드웨어 B]
   Agent (데몬으로 상시 실행)         Agent
   ├─ 주기적으로 CPU/메모리/로그 수집
   ├─ 중앙 서버로 Push (또는 서버의 Pull 요청에 응답)
   └─ 신뢰된 출처의 명령만 검증 후 실행
        │                              │
        └──────────► 중앙 서버 (본부) ◄──────────┘
              데이터 저장, 대시보드 표시, 명령 하달
```

## 정리

| 질문 | 답 |
|---|---|
| 에이전트는 어떤 프로그램? | 하드웨어에 상주하는 백그라운드 데몬 프로그램 |
| 주기적으로 정보를 보낸다? | 맞음 (Push 방식이 요즘 대세) |
| 화이트리스트 요청만 수행? | 맞음 (인증서/토큰으로 신뢰된 출처만 명령 수행) |
| 일종의 서버? | 방식에 따라 다름 — Push 방식이면 에이전트는 오히려 **클라이언트**, Pull 방식이면 요청을 받는 **작은 서버** 역할 |
